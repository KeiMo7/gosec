# Declarative custom rules — acceptance artifacts

This directory contains the full acceptance package for the configuration-driven
custom rule engine. Nothing here requires rebuilding gosec when a rule changes:
the rule set lives entirely in YAML files passed through `-custom-rules`.

## Layout

| Path | Purpose |
| --- | --- |
| `rules/01-anchors.yaml` | Rules G9001–G9006: the four anchor kinds, the untrusted-argument position and a multi-anchor rule. |
| `rules/02-exclusions.yaml` | Rules G9007–G9008: `arg_value` and `wrapper` exclusions; G9100 has no CWE to exercise the unclassified placeholder. |
| `sample/` | A small Go module with annotated hit / no-hit lines for every rule. |
| `invalid/` | Six illegal configurations (one per failure class) plus the cross-file duplicate-id pair. |
| `scripts/acceptance.sh` | Rebuilds gosec and runs every scenario, writing real output below. |
| `output/` | Generated artifacts: text/JSON/SARIF reports, filter runs, invalid-config rejections and runtime logs. |

## How to reproduce

```bash
./reports/scripts/acceptance.sh
```

The script exits non-zero if any invalid configuration is accepted or an
expected scenario fails.

## Rule language

```yaml
rules:
  - id: G9001                       # unique G<digits> id; collisions are a hard error
    description: shown on findings  # sourced verbatim into every issue
    severity: high                  # low | medium | high
    confidence: high                # low | medium | high
    cwe: "78"                       # numeric CWE id; omit for the unclassified placeholder
    anchors:
      - kind: package_call          # function call in a given import path
        package: os/exec
        function: Command
        arg_position: 0             # optional: fire only when this arg is untrusted
      - kind: method_call           # method on a receiver type ("*os.File" or "os/exec.Cmd")
        receiver_type: "*os.File"
        method: Chmod
      - kind: string_literal        # regex over string literal values
        pattern: "token-[a-z0-9]+"
      - kind: struct_tag            # regex over struct tag values
        tag_key: db                 # optional: restrict to one tag key
        pattern: "password"
    excludes:
      - kind: arg_value             # suppress on literal argument values
        arg_position: 0
        values: ["ls", "whoami"]
      - kind: wrapper               # suppress inside named wrapper functions
        arg_position: 0
        wrappers: ["safeExec", "main.safeExec"]
```

Multiple files are merged in lexical order. Any error rejects the whole load
and gosec refuses to start, pinpointing the file, entry index and field, for
example:

```
custom rules "invalid/01-unknown-anchor.yaml": rules[0].anchors[0].kind:
  unknown anchor kind "ast_walk"; expected one of package_call, ...
```

## Acceptance results (generated by `acceptance.sh`)

* Eight rules fire exactly as annotated in `sample/main.go`; the JSON report
  in `output/findings.json` carries severity, confidence, description and CWE
  from the configuration.
* Built-in rules (G302, G702, …) and custom rules (G90xx) appear in the same
  reports, statistics and SARIF output (`output/06-report.sarif`), and
  `#nosec G9001` suppresses a custom rule through the ordinary in-source
  suppression path (`output/02-mixed.json`).
* The six invalid configurations and the built-in id collision are all
  refused (`output/invalid-*.txt`, `output/05-collision.txt`).
* The rule without a CWE (G9100) reports the `CWE-0000 Unclassified`
  placeholder and emits a runtime warning (`output/01-scan-stderr.txt`).
* Anchors referencing packages/types absent from the target code never
  interrupt a scan; their misses are counted in the rule runtime stats, and
  regex evaluations run under a time budget that marks the rule skipped on
  timeout.
